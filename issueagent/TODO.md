# AI GitHub Issue Agent — Delivery TODO

- [x] **Application foundation and runtime** — The project contains separate `frontend/`, `backend/`, `database/`, `docker/`, and `docs/` areas; the frontend is React + TypeScript + Vite + Tailwind-compatible UI, the backend is Python 3.11+ FastAPI, the data layer is SQLAlchemy/Alembic with PostgreSQL as the Docker production database, `GET /health` returns non-secret status for application/database/GitHub/AI configuration, `GET /manus-routes.json` lists all page routes, and the application starts without fabricated provider data when credentials are unavailable.
- [x] **Authentication and protected access** — Users can register, log in, obtain a secure JWT-backed application session, log out, and access protected dashboard/repository/issue/analysis/settings routes only when authenticated; passwords are hashed and never stored in plaintext; invalid or missing JWTs return an appropriate error; tokens, passwords, and authorization headers never appear in logs or frontend responses.
- [x] **Real GitHub repository connection** — Users can securely submit a GitHub Personal Access Token, repository owner, and repository name; the backend validates access through GitHub, never returns or displays the PAT after saving, and displays live repository name, owner, description, default branch, primary language, stars, forks, open issues, and last-updated data; provider-unavailable and invalid-credential states are explicit and no repository data is hardcoded except clearly labeled demo mode.
- [x] **Repository dashboard and issue explorer** — The protected UI displays live recent/open issues, recently analyzed issues, generated solutions, and draft PRs; issue retrieval supports open/closed filters and title/number/label search; issue rows display number, title, description excerpt, labels, author, created/updated dates, comment count, and state; selecting an issue opens a detail page with live description, comments, labels, metadata, and an Analyze with AI action.
- [x] **Controlled AI issue analysis** — The backend cleans issue text, extracts keywords and likely technologies, searches relevant repository files/functions/classes/error messages/routes/models, retrieves bounded code chunks with filename/language/start_line/end_line/end_line/code fields, sends only relevant context to the configured OpenAI service, validates structured JSON with Pydantic, and returns summary, severity, root-cause hypothesis, affected files/functions, solution, implementation plan, testing plan, risk level, and provider/evidence status; prompt-injection content cannot directly execute arbitrary code; unavailable AI credentials produce a clearly labeled unavailable/demo response.
- [x] **Human-reviewed proposed changes and diff** — The system displays proposed file changes and a unified diff; generated changes are validated for safe paths, repository scope, size, patch shape, and default-branch protection; the UI requires explicit user approval after issue analysis and before branch/commit actions; no action silently modifies main/master/default branch and no automatic merge capability exists.
- [x] **Safe branch, patch, test, commit, and draft PR workflow** — After approval, the backend creates a new branch from the current default-branch SHA, applies only validated changes, runs configured tests in a bounded controlled process, displays test results, permits a commit only after successful validation, and permits creation of a GitHub draft PR only after a successful branch commit; the PR URL and status are displayed; branch/patch/test/PR failures are explicit and actionable.
- [x] **Frontend experience and API integration** — The product uses a professional developer-control-room layout with persistent navigation, repository/issue/analysis workspaces, safety status rail, IBM Plex Sans/Mono typography, accessible controls, loading/empty/error states, provider badges, diff/code viewers, workflow stepper, and responsive behavior; every major button calls a real backend API or shows a truthful unavailable/error state; no core workflow is a static UI mockup.
- [x] **Operations and documentation** — Docker Compose starts frontend, backend, and PostgreSQL; `.env.example` documents database, JWT, GitHub, OpenAI, frontend, and demo settings; README documents overview, architecture, features, environment setup, GitHub/OpenAI setup, Docker/local run, testing, security, limitations, and interview explanation; docs include architecture, API, database, security, AI workflow, GitHub workflow, and 20 technical interview questions with answers; `.env` is ignored.
- [x] **Testing and final verification** — Backend tests cover registration, login, JWT protection, GitHub service, issue retrieval, AI response validation, code search, patch validation, branch workflow, PR workflow, provider/error handling, unauthorized repositories, malicious paths, prompt injection, invalid patches, and default-branch safety; frontend checks/build/tests pass where configured; the app, health endpoint, route manifest, auth, demo/unavailable mode, and complete configured GitHub/OpenAI workflow are exercised; runtime errors are fixed before delivery and credential-dependent limitations are reported accurately.
