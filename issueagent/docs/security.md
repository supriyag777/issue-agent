# Security model

## Authentication

Passwords are hashed with Argon2 through `pwdlib`. JWTs are signed server-side and protected endpoints resolve the user from the database. Invalid, expired, or unknown-user tokens fail closed.

## Secrets

GitHub PATs are accepted only by the backend, sealed with Fernet before persistence, and never returned or logged. The OpenAI key is read only on the backend. Frontend builds receive no provider secrets. `.env` is ignored.

## Repository safety

Every write endpoint checks authenticated ownership and a stored workflow state. The branch name is generated by the server after approval; the default branch cannot be used as a mutation target. Repository paths reject absolute paths, traversal, NUL bytes, `.git`, workflow-control paths, oversized files, and oversized aggregate patches. There is no merge endpoint.

## AI safety

Issue text and source code are untrusted data. The model is told not to follow embedded instructions or call tools. Only bounded, relevance-ranked chunks are included. Output must parse as the Pydantic `AnalysisResult` schema before a change exists. The AI cannot execute code or directly call GitHub.

## Execution hardening

Production should run repository tests in an isolated worker/container with CPU, memory, filesystem, network, and timeout limits. This implementation uses structural validation when no configured worktree/test command is available and reports that limitation explicitly.

## Logging

Structured logs include request ID, operation, status, and duration. Passwords, PATs, OpenAI keys, authorization headers, and raw request secrets are excluded.
